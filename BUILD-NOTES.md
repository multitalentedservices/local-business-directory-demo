## Fictional directory
**The Gujranwala Gazette Directory** — a fictional city directory for Gujranwala (the owner's city), set in five named areas: Satellite Town, Model Town, Civil Lines, People's Colony and DHA Gujranwala. 18 fictional businesses, 3 in each of 6 categories (Restaurants & Cafés · Salons & Barbers · Clinics & Pharmacies · Auto Services · Home Services · Retail & Shops). Every name, address, phone, rating and review count is invented demo data, labelled as such on every page and again on the About honesty page.

- **"Clean Local — Gazette register":** a newspaper nameplate masthead with double rules and a dateline strip (city · printed demo clock · listing count), newsprint off-white paper `#FAF7EF`, black ink `#191817`, and ONE civic accent — deep teal-blue `#0B4F6C` (hover `#083C53`). Band `#EFE9DB`, card white, muted `#59524A`, hairline `#D9D0BE`; the only extra hue is the semantic error red `#B3261E`. - **Type:** Barlow Condensed (display, uppercase, newspaper-headline register — not used by any predecessor; Archivo and Space Grotesk were already taken) + Barlow (body grotesque).
- Distinctness: Gift Basket was cream/terracotta/emerald editorial commerce; Restaurant ink/parchment/brick + Fraunces; MTS black/white/lime poster; Salon porcelain/blush/bronze + Cormorant; Clinic white/petrol clinical; Real Estate navy/copper; Booking Engine slate SaaS skins; LMS paper/academic-green + Lora; Landing set grey/indigo/poster-orange ×3; Travel sand/plum + Playfair. This build's newsprint masthead + dateline + numbered category "shelves" + condensed gazette headlines could not be mistaken for any of them, and a search-led directory layout could not belong to a shop, clinic or LMS. The brief named the system "Clean Local" (shared with the clinic's brief) — the register, palette and type here are entirely this build's own execution of it.

## Features
- Pages (6): Home (search-led hero + numbered category tiles + featured listings), Browse & Search, Listing Detail (dynamic, `listing.html?id=`), Claim Your Listing (claim + suggest-a-business), My Claims & Enquiries, About This Demo (honesty page).
- Catalogue: 18 listings; text search (name/category/area/tags/services), category filter, area filter, open-now toggle, 3 sorts (featured / rating / name) — combined AND logic with live "Showing X of 18" counts; filter state kept in sync across controls, results and URL params (lesson 28); empty state names the exact active constraints ("category = Retail & Shops, area = Civil Lines") with one-click reset.
- Open-now: computed from each listing's Sunday hours against the printed fixed demo clock (Sunday 22 November 2026, 2:30 PM, lesson 29). Rule stated in the UI: open at or after opening, closed at exactly closing time. Glow Studio Salon's Sunday closing is exactly 2:30 PM, so it renders CLOSED NOW — the boundary case, battery-proven both sides (2:29 PM open / 2:30 PM closed; 10:00 AM open / 9:59 AM closed) and visible on its browse card. 12 of 18 listings are open at the demo instant; 5 are closed Sundays and Glow is closed at the boundary.
- Listing detail: full info, weekly hours table with today's (Sunday) row highlighted, services + tags, category photo, an honestly labelled static map placeholder panel ("Map placeholder — demo" — no external map embeds, no fake map screenshots, battery-asserted), enquiry form, WhatsApp button, claim route.
- Enquiry flow: validation names the constraint (name ≥ 3 chars, PK mobile 11 digits starting 03, message ≥ 10 chars) with live clearing; submission records locally (flow ref EN-DEMO-9068) and appears in My Enquiries with listing name + message (cross-surface).
- Claim flow: listing preselected from the detail page; claimant name, role (owner/manager), PK phone, business email, proof note — all validated as above; confirmation with deterministic-style ref (flow: CL-DEMO-3752), status "Pending review (demo)"; **cross-surface proof (lessons 30/38): claim state is one logic-owned record — the detail page's badge predicate (`claimPendingFor`) and My Claims read the same record; flow run captured the badge absent BEFORE the claim and "Claim pending (demo)" AFTER it, with before/after screenshots.**
- Suggest-a-business: validated form whose submission lands in My Claims as "New listing — pending (demo)" (flow ref CL-DEMO-5690) and provably does NOT enter the public catalogue — the flow run searched its name in Browse and got "Showing 0 of 18 listings"; the battery asserts the same in pure logic.
- WhatsApp: prefilled per-listing message to a demo number; the click is recorded in a local demo log (`ld_wa_log`) and asserted in the flow run (lesson 21). No sticky elements anywhere (lesson 35), so full-page captures are unstitched and clean.

## Disclosures
- One test assertion was amended during the build: the local-refs check initially matched a JS template fragment inside index.html's inline script (`'<img src="' + c.img …`) as if it were a file path. The check now skips refs containing quote/plus/space characters (template fragments), and the battery re-ran 157/157 PASS — disclosed here per lesson 9, not silently.
- Two rendered defects were caught by reading captures and fixed with re-capture: (1) the dark band's white panel inherited near-white paragraph text (a specificity leak — `section.band.dark p` beat the panel's note colour), fixed by scoping panel text colours; (2) the listing hero used an inline `grid-template-columns` style no media query could override (lesson 6), replaced with a `.detail` class + matching media rule, which also cleared the 320px h1 text-overflow; the homepage h1 floor was reduced to 36px at ≤560px for the same probe.
